DEDICATED REPLICAS ARE A PROVISIONING POLICY, NOT AN INHERENT LOWER BOUND
The current provision() reserves whole physical nodes for each independent
ORAM replica, including its exchange-wait time. An asynchronous worker pool
could cohost independent replicas while retaining separate mutable states.
All 530 replicas need about 1,174,763 GiB of modeled material per party; at
576 GiB usable per node that is 2040 nodes per party. Thus the CPU floor of
2312 nodes per party has enough aggregate memory for all 530 states. It might
be possible to approach this floor by using CPU/NIC time during other replicas'
round waits. Doing so while maintaining the latency objective requires a real
scheduler and contention measurements. This observation does not establish
that the $1.695B resource floor is feasible.
Sharing the mutable state of one ORAM among concurrent batches is a separate
protocol problem. The present model chooses independent ORAM copies. It does
not prove that every valid concurrent ORAM must duplicate the complete state.

SCAN BASELINE: USE SHARED IMMUTABLE DATA AND STREAMED TILES
For the same 32-byte key plus 32-byte value, each uses three 127-bit field
elements under the model's 126-bit payload packing. Six field elements with
16-byte values and 16-byte authentication shares give 192 bytes per record.
A dense N=2^28 read-only array is therefore 48 GiB per party before optional
flags and working buffers. It fits in one memory node and can be shared among
threads and concurrent queries; there is no reason to duplicate the full
immutable array for every batch worker.

Use public row shards and query tiles. Every party evaluates the same public
tile schedule; retain only a bounded tile's equality intermediates, and
accumulate partial output sums. A row/column tiling implementation can stream
network messages and avoid materializing N x B equality masks. Parallel query
workers share read-only arrays while keeping query/preprocessing state private.
Across machines, partition rows (and optionally replicate read-only shards to
scale query groups), and combine partial output sums. Count query fanout,
partial-result reductions, preprocessing, and actual network traffic.

At batch 128, the optimistic database-read lower bound from reading every
record only once per batch is 48 GiB * (10000/128) = 4.0265 TB/s per party.
Scanning the entire stored database separately for each query would instead
read 515.396 TB/s per party. Tiling can improve reuse substantially, but these
figures omit scratch traffic and say nothing about MPC equality cost.

Use the construction team's cheaper exact three-limb equality for the scan
baseline, rather than independently applying three Fermat equalities. For
p=2^127-1 (p=3 mod 4), set u=d0^2+d1^2 and v=u^2+d2^2 using two length-two
dot outputs. Since -1 is not a square, v=0 exactly when all three limbs are
zero. Then 1-v^(p-1) tests full-key equality using the existing 135-product
Fermat chain. This gives 137 outputs per row, or 36,775,657,472 outputs per
query at N=2^28. The simple 59/6-words/output traffic proxy gives about
5.786 TB sent per party per query, before payload selection and extra checks.
The dot outputs have additional local work, and the scalar/dot overhead must
follow the actual backend implementation. This is an improved baseline, not
a claim of optimal equality. Sharing immutable memory cannot itself remove
these cryptographic comparisons.

REPORTING RECOMMENDATION
Separate memory capacity from memory bandwidth, and both from weighted CPU,
communication, and dependent rounds. This fixed point is CPU-bound under its
assumptions, then limited by dependent-round latency. Its memory capacity is
large but not the active constraint at six nodes. Publish the resource vector
and assumptions first. The billion-dollar figures diagnose an expensive
arithmetic circuit/template plus a particular scheduler; they do not establish
that every honest-majority MPC design has this cost. Compare a properly tiled
scan baseline using shared immutable data, rather than mechanically applying
the ORAM state-replication policy to scans.
