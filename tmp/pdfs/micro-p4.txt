2.2. Byte-sliced Merge-split
Routing inside registers. Our main observation is that AVX-
512 can do more than move records as a whole. If we split
each record into bytes, one 512-bit register can hold the same
byte of 64 records. One permutation instruction, given an
index vector, then rearranges this byte of all the records at
once. Applying the same indices to each byte position rear-
ranges the whole records. We therefore use buckets of 64 slots
for our butterfly network. A merge-split then loads its two
input buckets from fixed locations, rearranges their records
in registers, and stores the two outputs at fixed locations. The
secret routing affects only the permutation indices, which stay
in registers, so the merge-split accesses the same memory
locations regardless of where its records go.
Byte-sliced layout. If each record were stored contiguously,
a merge-split would have to collect the same byte from 64
records, one load per record, before each permutation. We
instead store the buckets themselves byte-sliced (Figure 1):
the same byte position of all 64 slots is contiguous, so one
vector load fetches that byte for every slot. The hash tables
stay in this layout, so a merge-split loads its registers and
stores its outputs without converting any record. With w bytes
per slot, a bucket has w byte lines, each one 512-bit vector,
and a separate 64-bit occupancy mask. The mask identifies
real records, and the remaining slots are dummies. Each slot
contains a key, value, metadata that can mark the key absent,
and routing tag. A whole record occupies one column across
the byte lines. A lookup checks all 64 slots of a bucket at once
by comparing each key byte line with a register filled with
the corresponding byte of the requested key. It then extracts
the value with one byte permutation per value line, indexed
by the matching slot.
For a merge-split of buckets X and Y , we compute two
index vectors, π0 and π1, from the current routing-tag bit and
the occupancy masks. For each byte position, we load one byte
line from each input bucket. The two-source byte permutation
VPERMT2B selects each of its 64 output bytes from the 128
bytes in these two input registers [34]. Applying π0 produces
one output bucket’s byte line, and applying π1 produces the
other’s. The same two index vectors serve all w byte lines, so
each tag moves with its record. These permutations replace the
compaction or sorting network of depth at least log Z within
a conventional merge-split.
We size the tables for 32 records per bucket in expectation,
retaining the nominal half load used in prior butterfly-network
constructions [18]. Small buckets overflow frequently, so
we give each stage a fixed-capacity residual stash for the
records that do not fit, adapting NanoGRAM’s overflow col-
lection [21]. Section 2.4 describes these stashes and their
overflow bounds.
Planning the permutations. Output d ∈{0, 1} keeps the
records of X whose tag bit is d in their current slots and fills
its free slots, in order, with the corresponding records of Y .

selected bytes of Y and expand them into the free slots of
each output, which takes four compress/expand instructions
per byte position across the two outputs. We instead apply
one compress and one expand to slot indices, once for each
