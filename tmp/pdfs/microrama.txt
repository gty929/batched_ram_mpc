   The proof establishes that no key receives two real probes
under one hash for every request sequence, including repeated
keys within a batch, carries that keep their hash across publi-
cations, and tombstones at the top. Every real probe therefore
reads  its own uniformly random word, and every dummy
probe reads a fresh one. The view is then a fixed function
of distinct entries of a uniform tape, which gives  it exactly
the simulator’s distribution, and the capacity theorem bounds
the probability that MICRORAMA departs from this view.

Lookups return the newest value. For every request se-
quence and every choice of the hash words, each lookup
in the model returns the value of the newest record that the
initialization or an earlier request wrote for its key, or reports
the key absent if this record is a tombstone or does not exist.
In a batch, the earlier requests include those before the lookup
in the same batch. The proof formalizes the freshness order
of Section 3.4, including the tombstones that the top discards.
It also shows that these lookups touch exactly the buckets of
the view above, so the second theorem covers the accesses
that return these values.

Matching the model to the engine. A theorem about the
model says nothing about MICRORAMA unless the engine
computes what the model computes. For the bottom level’s
carry construction, we prove in Lean  that a transcription
of the native algorithm, over 64-bit words and bit masks,
produces exactly the model’s carry. For everything else, a
replay harness runs the engine, records every table it publishes
and every bucket each access touches, and compares them
with the model evaluated in Lean on the same requests. On
64 runs covering both of our configurations, branching factors
2, 4, and 8, initialization, batches, two rebuild schedules, and
forced overflows at every kind of merge, 7,053 published
tables match slot by slot, and each forced overflow fails in the
model at the same capacity. Across these runs, the touched
buckets and the real or dummy choice match the model at
every one of more than 5.3 million table probes, both when
merges run in pieces between accesses and when every merge
